# Local model evaluation: base vs fine-tuned (v1, v2) on held-out questions

Generated by `python -m src.finetune.evaluate`. One model, Qwen3-4B-Instruct-2507, in these setups:

- `base`: weights `models/Qwen3-4B-Instruct-2507-8bit`, no adapter
- `v1`: weights `models/Qwen3-4B-Instruct-2507-4bit`, LoRA adapter `models/adapters/bist-qwen3-4b-v1`
- `v2`: weights `models/Qwen3-4B-Instruct-2507-8bit`, LoRA adapter `models/adapters/bist-qwen3-4b-v2`

v1 was trained (MLX QLoRA) on the 4-bit weights and runs on them. v2 was trained on the full-precision weights (PEFT on a GPU) and runs on the 8-bit weights, which are closer to what it was trained on. The base model runs on the same 8-bit weights as v2, so base vs v2 differs only by the adapter; base vs v1 also differs in quantization.

Same settings as the live question mode: temperature 0, at most 6 tool calls, one correction round, max_tokens 3072.

**Held-out set** (`src/finetune/heldout.py`, `heldout.jsonl`): 40 questions written with phrasings, terms and a date format not used in training; no question shares category + stock/group + analysis date with any training or validation conversation. Gold tool calls and gold actions come from the same code and rules that produced the training data, so this measures whether the model applies the rules to new wording, not whether the rules are economically right. The instructor's five sample questions are in the training set and therefore not used here.

Calls with the unknown code in error questions are expected to fail and are not counted as invalid. Calls the model asked for after its 6-call budget was used up were refused by the harness and never run: they are counted on their own line, not as tool calls, not as invalid calls and not as evidence.
