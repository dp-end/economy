# Local model evaluation: base vs fine-tuned (v1, v3) on held-out questions

Generated by `python -m src.finetune.evaluate`. One model, Qwen3-4B-Instruct-2507, in these setups:

- `base`: weights `models/Qwen3-4B-Instruct-2507-4bit`, no adapter
- `v1`: weights `models/Qwen3-4B-Instruct-2507-4bit`, LoRA adapter `models/adapters/bist-qwen3-4b-v1`
- `v3`: weights `models/Qwen3-4B-Instruct-2507-4bit`, LoRA adapter `models/adapters/bist-qwen3-4b-v3`

All three setups run on the same 4-bit weights, so they differ only by the adapter. v1 was trained (MLX QLoRA) on these 4-bit weights. v3 was trained with PEFT on a GPU on the same 4-bit weights dequantized to fp16 (identical values), which avoids the quantization gap seen for v2. The system prompt and tool outputs are the current ones (rule-check line, success rates and the age of the last event/disclosure); v1 was trained before these changes and sees them here for the first time.

Same settings as the live question mode: temperature 0, at most 6 tool calls, one correction round, max_tokens 3072.

**Held-out set** (`src/finetune/heldout_v3.py`, `heldout.jsonl`): 60 questions written with phrasings and terms that are neither in the v3 training templates nor in the first held-out set, and a date format (10/09/2026) not used in training; no question shares category + stock/group + analysis date with any v1 or v3 training or validation conversation. Gold tool calls and gold actions come from the same code and rules that produced the training data, so this measures whether the model applies the rules to new wording, not whether the rules are economically right. The instructor's five sample questions are in the training set and therefore not used here.

Tool calls match when the tool name and every key argument of the gold call agree (stock/sector, event/pattern/strategy, horizon/lookback, conditions, dates stated in the question); extra valid arguments are allowed. Calls with the unknown code in error questions are expected to fail and are not counted as invalid. Calls the model asked for after its 6-call budget was used up were refused by the harness and never run: they are counted on their own line, not as tool calls, not as invalid calls and not as evidence.

## Reproducibility

- **base**: 10 questions run twice: same action 100.0%, same tool calls 100.0%, same answer text 100.0%.

- **v1**: 10 questions run twice: same action 100.0%, same tool calls 100.0%, same answer text 90.0%.
- **v1**: logged tool calls replayed under the same ceiling: same outputs 100.0%.
- **v3**: 10 questions run twice: same action 100.0%, same tool calls 100.0%, same answer text 90.0%.
- **v3**: logged tool calls replayed under the same ceiling: same outputs 100.0%.
