# Local model evaluation: base vs fine-tuned (v1, v4) on held-out questions

Generated by `python -m src.finetune.evaluate`. One model, Qwen3-4B-Instruct-2507, in these setups:

- `base`: weights `models/Qwen3-4B-Instruct-2507-4bit`, no adapter
- `v1`: weights `models/Qwen3-4B-Instruct-2507-4bit`, LoRA adapter `models/adapters/bist-qwen3-4b-v1`
- `v4`: weights `models/Qwen3-4B-Instruct-2507-4bit`, LoRA adapter `models/adapters/bist-qwen3-4b-v4`

All three setups run on the same 4-bit weights, so they differ only by the adapter. v1 was trained (MLX QLoRA) on these 4-bit weights; v4 was trained like v3 (PEFT on a GPU on the dequantized 4-bit weights) on the v4 data: error-fix conversations (a deliberately broken call, the real tool error, the corrected call; the broken call is not in the loss), generated weekday-pattern sentences and short-period exchange-rate claims. The system prompt is the current one (fix and retry correctable tool errors, default start 2024-01-01, three actions for fundamentals questions); v1 was trained before these changes and sees them here for the first time.

Same settings as the live question mode: temperature 0, at most 6 tool calls, one correction round, max_tokens 3072.

**Held-out set** (`src/finetune/heldout_v4.py`, `heldout.jsonl`): 60 questions written with phrasings, terms and weekday-pattern wording that are in neither the v4 training data nor the earlier held-out sets, patterns drawn uniformly from all 132 valid weekday patterns, and a date format (10/09/2026) not used in training; no question shares category + stock/group + analysis date with any v1 or v4 training or validation conversation. The v4 data fixes were designed after looking at the errors on the v3 held-out set, which is why that set is not used here. Gold tool calls and gold actions come from the same code and rules that produced the training data, so this measures whether the model applies the rules to new wording, not whether the rules are economically right. The instructor's five sample questions are in the training set and therefore not used here.

Calls with the unknown code in error questions are expected to fail and are not counted as invalid. Calls the model asked for after its 6-call budget was used up were refused by the harness and never run: they are counted on their own line, not as tool calls, not as invalid calls and not as evidence.

- **v4**: logged tool calls replayed under the same ceiling: same outputs 100.0%.
